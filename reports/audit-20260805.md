### MINOR-1 — `reuse lint` is red (exit 1); `.gitignore` omits two build trees
Commit range (build dirs created during M3/windowed work) + pre-existing residue.
`reuse lint` exits **1** (non-compliant), contradicting GOAL's "reuse lint stays green".
Root causes, in order of volume:
- `.gitignore` lists `build-wasm/`, `build-dawn/`, `build-deps/`, `build-native-gpu/` etc.
  but **omits `build-wasm-gpu/` and `build-wasm-windowed/`** — ~13,200 untracked build
  artifacts (`.ninja_*`, `CMakeCache.txt`, `*.wasm`) that pollute the lint. Not tracked
  (0 files under `git ls-files`), so a clean CI checkout would not carry them, but the gap
  also risks an accidental 13k-file commit.
- Independent of build dirs, two committed-state items keep the lint red on a clean tree too:
  `Unused licenses: MIT` (the `sandbox/memory64-probe/fmt-12.1.0/**` MIT annotation points at
  an untracked/absent tree), and one tracked uncovered file
  `sandbox/memory64-probe/README.md` (`*.md` is not in the `sandbox/**` glob list; added in
  `b75ef36`, **before** this range).

Why it matters: M8's gate requires compliance green. **No addition from the last 25 commits is
itself unlicensed** — patches are covered by the `patches/*.patch` glob, ADR-005 carries an
inline CC0 header, the evidence PNG/TXT match the `sandbox/**` globs, and the lane-A
`.cc/.hh` carry proper dual SPDX headers (verified). Fix is `.gitignore` + REUSE.toml
extensions (`sandbox/**/*.md`, `*.err`), not any source change.

### MINOR-2 — `generate_mipmap` silently no-ops for multi-mip textures (no runtime guard)
`upstream/source/blender/gpu/webgpu/wgpu_texture.cc:1262` — `generate_mipmap` is a no-op
("No-op for now … single-mip textures are unaffected. needs blit pipeline"). It **is**
documented in-code and has a notes trail (`ledger/progress.txt:137`,
`notes/gpu-laneB-integration.md:126`), so it clears the "documented no-op" bar. But unlike
the sibling deferral `pixelbuf update_sub` (line 968) which `BLI_assert_msg(0, …)` fails
loudly, and unlike `snorm16` which has a formal `ledger/deferred.json` entry, this one
would produce **silently wrong results** if a multi-mip texture is ever sampled before the
blit path lands, with no assert and no deferral-registry visibility. Low risk at current M3
scope (mip-sampling not yet exercised); flag before any milestone that renders mipmapped
textures. Suggest a `ledger/deferred.json` entry or a multi-mip `BLI_assert`.

## Checked and CLEAN (coverage map)

**Parity theater (finding #1) — all four flagged items are principled, not test-shaped:**
- **Y-flip pair 0044/0045/0052** — matches ADR-005 exactly. Single clip-space `gl_Position.y`
  negation (0052) is the standard GL→WebGPU convention, alongside the depth remap that was
  already present; front-face CW↔CCW swap (0044) correctly compensates the winding inversion;
  readback row-flip (0045) is **gated to the render-target path** (`WGPUFrameBuffer::read`
  only — comment + code confirm `WGPUTexture::read` upload→read stays symmetric). ADR-005
  explicitly *rejects* "adjusting test expectations" as forbidden theater. **Re-ran
  `GPUWebGPUTest.*roundtrip*`: 51 PASS / 2 FAIL** — the 2 fails are the pre-characterized
  depth-format gaps (`GPU_DEPTH_COMPONENT32F`, `GPU_DEPTH32F_STENCIL8`, progress.txt round-5),
  not a Y-flip regression → decision 3 ("do not regress the passing texture tests") holds.
- **NAN_FLT guard 0054** — preserves NaN semantics. Routes `0x7FC00000` through a mutable var
  so glslang cannot const-fold a Tint-illegal NaN literal; the runtime `OpBitcast` still
  yields the exact NaN bit pattern via legal WGSL `bitcast<f32>()`. Gated `#ifdef GPU_WEBGPU`;
  other backends keep the plain macro. Not a dodge. "nan bucket 32→0" is internally coherent
  (513−481 = 32).
- **SNORM16-as-Uint emulation 0016b** — documented in `ledger/deferred.json`
  (`id: snorm16-texture-formats`) with blocker/impact/workaround/revisit; stores byte-identical
  snorm bits in a matching-width Uint (the registry's own workaround #1), not a fake.
- **blend 12/12** — the oracle `upstream/source/blender/gpu/tests/state_blend_test.cc` is
  **byte-identical to the pin** (`git diff` empty; no patch modifies it — the 0022 grep hit is
  incidental). Its one real assertion `EXPECT_EQ(read_back, expected_result)` (line 50) runs
  per blend mode. **Re-ran `GPUWebGPUTest.*blend*`: 12/12 PASSED (666 ms).**

**Test harness not weakened:** `gpu_testing.hh` change (0022) adds `GPUWebGPUTest` running the
**identical** `test_##name()` bodies via standard `TEST_F`, appended to the `GPU_TEST`
composite — WebGPU held to the same assertions as Metal/Vulkan/GL. **No `GTEST_SKIP`,
`DISABLED_`, or blacklist added by any patch** (grep across all patches empty).

  before any milestone that rebuilds the port from patches on a fresh pin.
