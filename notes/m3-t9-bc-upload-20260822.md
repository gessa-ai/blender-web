## Outcome

Patch 0170 closes a silent compressed-texture path in the registered WebGPU backend.
Blender's DDS loader obtains existing BC1/BC2/BC3 blocks and calls
`GPU_texture_create_compressed_2d`; the pinned frontend then walks every mip and passes its exact
block range to `Texture::update_sub`. `WGPUTexture::update_sub` previously returned immediately
for `Repr::Compressed`, so allocation could succeed while every mip remained unwritten.

The backend now computes the physical 4x4 copy extent and block-row layout required by the pinned
Dawn implementation, preserves the caller's BC bytes, and submits them with `Queue::WriteTexture`.
Origins must be block-aligned; a partial final block is accepted only at the logical mip edge;
source row length, array layers, physical bounds, and all size products are checked before the
queue call. BC1 uses eight-byte blocks and BC2/BC3 use sixteen-byte blocks through the canonical
format table.

Compressed allocation is limited to WebGPU's 2D texture family and requires the device's
`TextureCompressionBC` feature. If either condition is absent, allocation fails before upload so
the pinned image caller reaches its existing uncompressed fallback instead of receiving a valid
but empty texture. No behavior changes for non-compressed formats.

## Boundary

browser receipt, or milestone result. A live compressed upload/sample/readback remains owned by
`M3-LINUX-REPLAY` and requires the s7 hardware adapter; ornith-lab still exposes only llvmpipe.
