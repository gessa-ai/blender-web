## Findings

### MAJOR-1 - presentation preflight treats optional telemetry as deterministic validation

Commit `645e2da` moved persistent-backbuffer scopes before canvas configuration to avoid the
software adapter's post-configuration error-scope failure. It now listens for
`uncapturederror`, calls `surface.configure()` and `getCurrentTexture()`, waits exactly one
`setTimeout(0)` turn, then removes the listener and publishes status 5
(`platform_web/shell/wgpu-preinit-worker.js:303-337`).

That cannot establish the claimed strict configuration result. The current
[WebGPU error model](https://www.w3.org/TR/webgpu/#uncapturederror) defines uncaptured-error
events as telemetry: a user agent may omit or throttle them, and applications should not use
them to handle known error cases. A configuration error delivered after the single timer turn,
or not exposed as an event, is therefore accepted. The 11-case worker model makes the
configuration error fire synchronously inside `configure()`
(`sandbox/wgpu-pipeline-integrated-smoke/preinit_worker_test.mjs:63-70`), so it cannot expose
this timing/omission hole.

The correction must validate actual surface use through a deterministic browser/device
completion boundary without reintroducing the software-adapter crash. The source contract must
include delayed and omitted telemetry controls and must not call optional telemetry a strict
success signal.

### MAJOR-2 - the P0 live diagnostic accepts a one-tick-dead WM loop

The headed verifier waits six seconds after `state=running`, reads `_bw_wm_tick_count()` once,
and accepts any value greater than zero
(`sandbox/wgpu-pipeline-integrated-smoke/live_preinit_boot.mjs:70-90`). The counter is incremented
by the actual main-loop body (`platform_web/ghost/GHOST_SystemWeb.cc:129,339-341`). A process that
enters that body once and then stalls therefore passes.

This is not hypothetical evidence shape: the recorded P0 diagnostic says `ticks=1`. It proves
that the stage-1 boot abort is gone and `WM_main` was entered, but not that the shipping event
loop remained live. The corrective receipt must sample at least twice after the running state,
require a positive bounded delta, and complete one input/redraw round trip. A software adapter
may remain diagnostic-only; it must not bind a GPU receipt.

### MAJOR-3 - axis-target pairs old depth with later selection and transforms

`object_transform_axis_target_depth_context_matches()` checks window/view/depsgraph/scene/
view-layer/active-object pointer identity only
(`upstream/source/blender/editors/object/object_transform.cc:2181-2196`). Selection enumeration
and transform backups are intentionally delayed until readback settlement
(`object_transform.cc:2282-2302`). A frame step, selection mutation, or same-object transform
change can preserve every checked pointer while causing old depth to initialize a different
operation state.

The focused verifier requires the delayed capture
(`sandbox/m5-object-axis-target-depth-cache/verify_source.py:123-153`), and its synthetic model
does not represent mutable frame, selection, or transform generations. Capture safe producer
identities/state before suspension and fail closed if that state changes before consumption;
add same-pointer frame, selection-set, and transform mutations.

### MAJOR-4 - particle-edit sessions pair old depth with current mutable edit state

`ParticleEditDepthCacheSession` retains producer pointers and x-ray state but no frame,
object-transform, or edit-data generation
(`upstream/source/blender/editors/physics/particle_edit.cc:505-523`). Its context guard checks
those identities and the same `PTCacheEdit *` (`particle_edit.cc:550-570`), then reconstructs
`PEData` from current state immediately before taking old depth
(`particle_edit.cc:653-666`). Particle positions/topology, frame, or object transform can change
without replacing that edit pointer. Click, linked-pick, box, lasso, circle, and brush paths all
inherit the mismatch.

The focused model contains only pointer-like identities and x-ray state
(`sandbox/m5-particle-edit-depth-cache/contract_test.cc:18-54`). Add a conservative producer-state
token or explicit frame/transform/edit-generation validation, plus same-pointer mutation cases
covering click, gesture, and brush continuations.
