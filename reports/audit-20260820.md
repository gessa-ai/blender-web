## Findings

### MAJOR-1 - the cold migration runbook omitted the native host-tool build (FIXED)

The section-5 dependency shell exports `CXX=em++`, completes the Wasm harvest, and then invoked
`scripts/build-locale-datafiles.sh` directly. It never invoked `scripts/build-hosttools.sh`, even
though the locale script fails closed unless `build-hosttools/bin-native/msgfmt` already exists.
Calling the host-tool script naively in that shell would also inherit `em++`, contrary to
ADR-002 and the recorded clang++-17 host-tool identity.

The range also made `msgfmt` link `-lz -lzstd` (`682f9f1`) while the runbook's package list
omitted `zlib1g-dev` and `libzstd-dev`. The adjacent source comment still claimed that zstd was
not linked. Thus the checked-in cold-start authority could not reproduce the already-working
machine state without undocumented manual intervention.

Fixed in this audit:

- add both native development packages to section 3;
- after the Wasm dependency harvest, build host tools through `harness/buildwrap.sh` with an
  explicit `CXX=clang++-17`, then build locale catalogs through the wrapper;
- document the generated host-tool outputs and the host/target compiler seam in
  `notes/porting-patterns.md`;
- correct the stale zlib/zstd linker comment.

Re-execution on ornith-lab produced three Linux ELF host tools and 49 catalogs totaling
80,448,982 bytes; the Japanese catalog magic is `0x950412de` and the languages index is 2,248
bytes. The host-tool and locale logs are `20260820T144409` and `20260820T144514`.

### MAJOR-3 - `buildwrap.sh` can overwrite evidence from the same second (RESOLVED, `2bd738f`)

The protected wrapper names logs only with `date -u +%Y%m%dT%H%M%S`. Two fast self-checks in
this audit both reported `ledger/buildlogs/20260820T143756.log`; the second truncated and
replaced the first. Concurrent fleet builds starting in one second can also write the same file.
This falsifies the wrapper contract that every invocation retains its full log and can destroy
the evidence behind otherwise-correct receipts.

The audited receipts' cited logs use distinct names, so no M0-M2 claim in this range is invalidated.
For this audit, the overwritten runner check was rerun under unique log `20260820T144007`; the
remaining verifier checks retain distinct logs. The repair belongs in a sanctioned harness
lock-lift: allocate logs exclusively (for example timestamp plus PID and an atomic no-clobber
suffix) and add a same-second/concurrent negative fixture. This audit does not edit protected
`harness/` code.

Resolved on 2026-08-20 through the documented driver lock-lift. The wrapper now reserves
timestamp/PID/suffix paths atomically, and a frozen-clock fixture preserves exact content in
4 sequential, 32 concurrent, and 16 forced-same-basename logs. The lock was restored before
commit.
