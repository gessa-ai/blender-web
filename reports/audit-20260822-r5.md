## Major — offscreen rectangle origins were inverted

Commits `032c45f` and `f49670a` treated ordinary offscreen viewport/scissor and scissored-clear Y
as already suitable for WebGPU. That composed two independent orientation operations incorrectly:

- pinned Dawn stores `SetViewport` and `SetScissorRect` coordinates verbatim
  (`build-dawn/dawn/src/dawn/native/RenderPassEncoder.cpp:285-291,316-321`), then maps them to the
  backend top-origin rectangle (`d3d12/CommandBufferD3D12.cpp:2091-2113` and
  `vulkan/CommandBufferVk.cpp:2068-2104`);
- Blender's WebGPU framebuffer path documents source row zero as the top and reverses rows for the
  GL-compatible result (`upstream/source/blender/gpu/webgpu/wgpu_framebuffer.cc:1002-1009`,
  `wgpu_common.hh:1039-1043`).

Therefore a WebGPU source interval `[t,t+h)` is observed at Blender Y `[H-t-h,H-t)`. For the exact
5-row contract, Blender `y=1,h=2` must be emitted as WebGPU `top=2`; the audited helpers emitted
`top=1`, which reads back at Blender rows `[2,4)` instead of `[1,3)`. Vertex clip-Y reflection can
change content orientation inside a viewport but cannot relocate the viewport. The fullscreen
clear WGSL does not use that specialization at all.

Patch 0201 removes the `convert_bottom_origin` policy switch. Both ordinary window and offscreen
plans now use the same widened `H-y-h` transform, and every scissored clear does likewise. The
pipeline and texture drivers failed first on the old conditional policy
(`20260822T212853-1923852`, `20260822T212857-1924511`) and now pass byte-identical native/wasm32
contracts (`20260822T213852-1935977`, `20260822T213904-1937033`). The 6x5 cases explicitly require
the corrected offscreen viewport and color/depth/stencil clear origins.

## Minor fixed — null scissored-clear pipelines poisoned retries

Commit `f49670a` inserted both newly created scissored-clear pipelines into their caches before
testing the handle. A transient null result therefore left a permanent matching cache entry; every
later clear loaded null, skipped creation, and returned without clearing. Patch 0202 checks the
local candidate before either cache publication (`wgpu_framebuffer.cc:275-280,436-441`). The new
source-order contract reproduces the old publication order (`20260822T213609-1933648`) and is
green in the final texture contract (`20260822T213904-1937033`). No device or pipeline receipt is
claimed.

## Minor queued — empty raster state skips pending load clears

Commits `bfb4f27`, `743796b`, and `032c45f` reject zero or fully clipped viewport/scissor state
before `WGPUFrameBuffer::begin_load_pass()` reaches `materialize_layered_loadstore_clears()`
(`wgpu_common.hh:236-248`; `wgpu_framebuffer.cc:1409-1446`). Pinned Dawn explicitly accepts zero
viewport and scissor extents
(`build-dawn/dawn/src/dawn/tests/unittests/validation/DynamicStateCommandValidationTests.cpp:92-101,220-229`).
Every successful ordinary-pass caller continues to its normal draw, so representing valid-empty
state is safe: preserve a validated zero viewport, or install a contained `(0,0,0,0)` scissor for
a fully clipped enabled scissor. The pass then consumes load operations while rasterizing zero
fragments.

The current early return can leave a pending `GPU_LOADACTION_CLEAR` unconsumed and stale pixels
observable until a later pass. `M3.T10-EMPTY-RASTER-LOADOP` records the exact bind-loadstore,
zero-raster, readback regression and is intentionally left as the next small implementation task;
it is not concealed behind the hardware blocker.
